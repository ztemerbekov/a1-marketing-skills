# Landing Page Copy Spine

Every completed run follows these stages in order.

## 1. Classify the Page Job

Confirm one new page, one offer, one primary audience, and one principal next action. Select Blueprint or Draft and record explicit constraints on length, format, voice, mandatory blocks, and conversion action.

Do not split an unclear offer into invented products or choose among materially different audiences by guesswork. Ask one concise question only when the page would otherwise make an arbitrary product decision.

**Complete when:** the offer, primary audience, action, output mode, and neighboring-skill boundary are clear.

## 2. Build the Offer Map

Read [source-policy.md](source-policy.md). Map product facts, reader outcomes, proof, terms, fit limits, transaction details, and source gaps.

**Complete when:** every allowed promise and transaction detail has a traceable source and unsupported persuasion assets are excluded.

## 3. Set the Page Proposition

Formulate an internal working proposition:

`For [primary reader in a situation], this [plain-language category] helps [supported useful outcome] through [supported mechanism or differentiator].`

This is a reasoning aid, not a mandatory headline. Keep the proposition within the offer map.

**Complete when:** the page has one direction that can govern block selection and ordering.

## 4. Build the Page Path

Read [page-architecture.md](page-architecture.md). Choose and order only the blocks needed to move the reader from orientation through evaluation to transaction. Attach evidence and a useful visual or artifact to important claims.

In Blueprint mode, skip drafting after checking that every critical buying question has a supported place in the page, then continue to final QA.

**Complete when:** each block answers a real reader question, adds new information, and advances evaluation or action.

## 5. Draft the Copy

Write concrete headings and copy in page order. Show the offer in use, explain mechanisms and consequences, preserve fit limits, and make the transaction operational.

Keep design notes separate from publishable copy. Do not use prose to compensate for missing product facts or evidence.

**Complete when:** the reader can identify what the offer is, whether it fits, why the claims are credible, what it costs or requires, and what happens after acting.

## 6. Run Final QA

Run [final-qa.md](final-qa.md) and revise until every applicable check passes.

**Complete when:** the page is focused, source-faithful, persuasive through evidence, transparent about terms, and compliant with `../SKILL.md`.
