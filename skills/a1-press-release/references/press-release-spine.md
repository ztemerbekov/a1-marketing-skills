# Press-Release Spine

Every completed run follows these stages in order.

## 1. Qualify the Request

Confirm that the request is a routine press release or event announcement and does not fall into the excluded crisis, legal, regulatory, earnings, securities, or investor-relations categories in `../SKILL.md`.

Identify the intended media audience and the concrete event or change. If the material contains only a general desire for publicity, state that a release needs a specific news event and ask for it.

**Complete when:** the request is in scope and one source-supported event anchors the release.

## 2. Build the News and Readiness Map

Read [source-policy.md](source-policy.md). Map the event, affected audience, timing, place, significance, facts, action, quotation status, boilerplate, contact, assets, and pre-distribution checks. Classify every distribution-critical input as confirmed, approved where permission is required, or unresolved; then determine whether the result is ready for distribution or remains a working draft.

**Complete when:** every distribution-critical element has a readiness status, the output state follows from those statuses, and unresolved material is excluded from authoritative prose.

## 3. Set the News Angle

Choose the most relevant source-supported consequence for the intended media audience. The angle should reveal why this event deserves attention without overstating novelty or importance.

**Complete when:** one sentence can state what happened and why this audience may care.

## 4. Draft the Release

Read [release-structure.md](release-structure.md). Write the headline and lead first, then body sections ordered by media usefulness. Add an approved quote only when it contributes information. In a working draft, add proposed spokesperson wording only when the user explicitly requests it and mark it unmistakably for approval. End with action, boilerplate, contact, and asset links when supplied.

**Complete when:** the headline and lead stand alone, the body offers reusable verified detail, and the next action or contact is operational.

## 5. Run Final QA

Run [final-qa.md](final-qa.md) and revise until every applicable check passes.

**Complete when:** the result is accurate, extractable, within scope, labeled at its actual readiness, and compliant with the output contract in `../SKILL.md`.
